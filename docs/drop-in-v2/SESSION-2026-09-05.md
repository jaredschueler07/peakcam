# Drop In v3 — 2026-09-05

## What shipped

Implemented on the local feature branch; not deployed. Created isolated
`.worktrees/drop-in-v3` on `feat/drop-in-v3` from main `de795d4`; the primary
checkout and snowing-now work remain separate. Bounded phase branches were
independently reviewed and integrated with `--no-ff` merges and saved diff stats.

- Full mapped downhill network and stable course IDs: 230 selectable named pieces
  at Breckenridge, 128 at Heavenly and six at Portillo. Width defaults, incomplete
  source coverage and forest assumptions are documented in bake provenance.
- Seeded corridor banks, moguls, rock relief and tree wells share the same DEM
  with collision and analytic normals. Final forest sites: 6,130 / 7,331 / zero.
  Terrain packs plus the shared pine atlas remain below 1.8 MB per resort.
- All 72 complete mapped lifts have normal proximity boarding, continuous
  fixed-step rides and terminal unloading. Real carrier types, station names,
  towers, cable sag, junction signs and boundary ropes are rendered.
- Physics v2 is the default on a shared 120 Hz integrator. Versioned historical
  fixtures remain; PHYSICS_VERSION=2 and COURSE_VERSION=3 segment new boards.
  Server-side input replay now validates the actual quantized input tape against
  recorded poses and scores, including signed powder/wind/ice conditions.
- Time Trial conditions are fixed. Daily Line reads an immutable resort-local
  morning snapshot; its migration and scheduled capture require deployment.
- Reversible quality transitions, low-rung WebGPU AA, textured conifer impostors,
  mineral rocks, sourced lake outlines and Portillo hotel footprint, corduroy,
  persistent ski grooves, ballistic spray, wind/audio/landing feedback.
- Native route default and legacy iframe/vendor removal; named course/elevation
  HUD, lift/junction overlays, signed run freeze, focus traps and touch handling.
  PR CI runs unit/type/import-fence/build and production WebGL/heap checks.

Local acceptance passed on the final gameplay build `aed2b3d`: 1,099 unit tests,
TypeScript, import fences, production build, 43 browser tests and all six unchanged
weather=0 luminance guards. The full real-input matrix passed 36/36 combinations
of resort, mode, backend and keyboard/touch, with zero browser errors or debug
mutations. Competitive UI tickets were mocked; real authenticated handler acceptance
and tamper rejection were verified separately with in-memory dependencies.

All 72 lifts passed accelerated browser boarding, continuous fixed-step traversal
and genuine terminal unload, with endpoint error below 1e-12 m. Imperial SuperChair
runs for 333.83 simulated seconds. This is simulation-path coverage, not 72
human-paced rides.

Final clear-weather captures cover all three resorts and both backends at 750 ms,
5 seconds and 30 seconds. Reversible 4→1→4 quality transitions were inspected.
Storm samples pass desktop draw/triangle/texture budgets and mobile-emulation
draw/triangle budgets. Desktop WebGPU rung 4 p95 is 9.8–10.0 ms on Apple M4 / 16 GB.
The mobile viewport uses the same GPU and does not certify Android performance.
Cold navigation to the no-query game took 2.78 seconds with an empty browser cache,
10 Mbps down / 1 Mbps up and 100 ms latency, passing the stricter three-second budget.

Detailed measurements, methods, reproducible scripts and remaining release gates:
[V3-QA.md](V3-QA.md). No production leaderboard writes were made.

## What was learned

- The base lacked the background's shared integrator and authoritative tape
  replay. Both were brought forward with legacy parity and tamper checks.
- GPU screenshots exposed far-field overdraw hiding the skier, invulnerability
  blinking at startup, broad ribbon-like tracks and a premature running HUD.
  Unit tests alone would not have found these visible failures.
- A candidate tree atlas used a restricted site preview. It was removed and
  replaced by verified actual CC0 twig/alpha assets with recorded provenance.
  Current assets use no restricted preview and introduce no paid dependency.
- OSM has richer trail coverage than the former six-run menu, but often omits
  widths, tower details and local forest polygons. Defaults and source gaps are
  explicit; illustrative vegetation is not claimed to be a botanical survey.

- Real multi-touch runs exposed Tuck stealing the active steering pointer. Interactive
  controls and subsequent pointers now leave steering capture intact; actual two-finger
  runs and pointer lifecycle tests cover both press orders.
- Bicubic physics heights can differ from the rendered 4 m / 8 m triangle surface.
  Grounded ski contact now samples the rendered triangles and preserves the canonical
  simulation and replay position. Startup and Portillo screenshots verified the fix.
- Resource checks need whole-frame counters and real mobile DPR. Hidden WebGL effects
  were still allocating/rendering despite skipped blending; explicit reversible gates,
  cable batching and far-field index LOD brought sampled views under budget.
