## What was learned

- The base lacked the background's shared integrator and authoritative tape
  replay. Both were brought forward with legacy parity and tamper checks.
- GPU screenshots exposed far-field overdraw hiding the skier, invulnerability
  blinking at startup, broad ribbon-like tracks and a premature running HUD.
  Unit tests alone would not have found these visible failures.
- A candidate tree atlas used a restricted site preview. It was removed and
  replaced by verified actual CC0 twig/alpha assets with recorded provenance.
  Current assets use no restricted preview and introduce no paid dependency.
- OSM has richer trail coverage than the former six-run menu, but often omits
  widths, tower details and local forest polygons. Defaults and source gaps are
  explicit; illustrative vegetation is not claimed to be a botanical survey.

- Real multi-touch runs exposed Tuck stealing the active steering pointer. Interactive
  controls and subsequent pointers now leave steering capture intact; actual two-finger
  runs and pointer lifecycle tests cover both press orders.
- Bicubic physics heights can differ from the rendered 4 m / 8 m triangle surface.
  Grounded ski contact now samples the rendered triangles and preserves the canonical
  simulation and replay position. Startup and Portillo screenshots verified the fix.
- Resource checks need whole-frame counters and real mobile DPR. Hidden WebGL effects
  were still allocating/rendering despite skipped blending; explicit reversible gates,
  cable batching and far-field index LOD brought sampled views under budget.

## Follow-up — steering direction

The chase camera looks along the skier's +Z forward axis, so positive simulation
yaw is a visible left turn. Input adapters previously sent screen-right-positive
values directly to that yaw convention, reversing left/right controls. Convert
once in InputManager before recording: left/A/left drag now turns left, and
right/D/right drag turns right. Mouse and gamepad share the correction. Physics
and existing input tapes retain their conventions, so no model version bump is
needed. Updated the automated full-run controller to use the corrected controls.

Regression coverage projects the actual integrator's heading change onto the
actual chase camera's right axis at five headings, for four input sources in both
directions. All eight cases failed before the fix and pass after it. Focused
input, golden physics and authoritative replay suite: 180/180 passed. TypeScript,
ESLint and production build pass. Real arrow/A/D presses and CDP touch drags pass
all 12 direction cases on WebGL and WebGPU; no debug movement is used.

Full Imperial Bowl descents also pass with both keyboard and two-finger touch
on WebGL using the corrected controls: 2/2, no browser errors or debug mutations.

## Follow-up — descent progress meter

Added a visible bar above the run statistics showing percent descended and
vertical feet left to the selected run's bottom. It uses the existing DEM
altitude and run top/bottom elevations, stays clamped to 0–100%, updates off-piste
and on lifts, and resets naturally with the run. It is vertical descent progress,
not race distance or checkpoint completion. Screen-reader value text identifies
the selected run; reduced motion disables the bar transition. Junction prompts
move up to clear the enlarged statistics panel.

TypeScript and focused ESLint pass. Real-GPU browser checks pass at 1365×900
(WebGPU), 390×844 and 320×740 (WebGL): 0% at start, 9–10% after descending,
reset to the top, no overlap or browser errors. All three screenshots inspected.
Reproduce with `.superpowers/sdd/V3-PLAN/descent-meter-qa.mjs` against port 3113.
Two full production-build attempts compiled successfully but failed during
unrelated homepage/resort/sitemap prerendering because Supabase queries timed
out. This follow-up's visual validation uses the isolated development preview,
now serving port 3113; production-build acceptance remains blocked by that
external dependency. No primary checkout or database changes were made.
